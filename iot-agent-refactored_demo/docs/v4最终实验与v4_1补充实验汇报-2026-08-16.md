## 3. v4.1 原始文本 Ingestion 补充实验

### 协议与审计

- 协议：`experiments/configs/protocol_v4_1_supplemental_ingestion.json`，在运行前固定 3 条轨迹、7 个系统和 replicate `1001-1010`。
- 冻结 revision：`48cc3b49ffd0c759791710ce06fab1435178a17b`。
- 结果根：`experiments/results/protocol_v4_1_supplemental_48cc3b4_20260816/`。
- 矩阵：`Ours+B0-B5 × I1-I3 × 10 = 210` unit；`210/210` 观察到，final audit=`pass`。
- 所有 canonical unit 使用 `newapi / gpt-5.4-mini / external_llm`；无 heuristic fallback、无 usage 缺失、无 runtime `memory_ops`/`action_template`/evaluator 标签。
- B1 强制 raw-text RAG，B4 强制 full raw history；fidelity audit 通过。1 个 B1 unit 和 1 个 B4 unit 发生 transport timeout：原失败尝试保留，受限 repair 后 canonical trace 有完整 usage。总 canonical 调用 `210` 次，canonical tokens=`1,767,752`；共记录 `219` 次 transport attempts、`1` 个 repair unit。

三条冻结轨迹：I1 明确偏好创建（卧室 24 度）、I2 自然语言纠正（卧室 26 度）、I3 跨实体偏好（客厅 22 度和卧室 25 度，查询卧室）。该 ingestion 目前是规则型温度偏好创建/纠正，不是通用 LLM extraction，也不是产品 runtime。

### 对主结论的影响

v4.1 不改变 v4 behavioral 主表，因为它引入的是一个独立 raw-text ingestion workload，系统输入和覆盖范围不同，任何 unit 均未和 v4 behavioral 合并。

它改变的是论文对 ingestion 的表述边界：不能声称当前 Ours 的规则型 raw-text ingestion 在此 workload 中优于 B1 或 B4。可以如实写为：Ours 在 I1/I2 的明确创建和纠正上稳定成功，但在 I3 的跨实体选择上 0/10；B1 和 B4 在 I3 上分别为 7/10 与 6/10，因此该补充实验暴露了 Ours 的 entity selection/ingestion 路径缺口。
