## 产品 Runtime

- 入口是 `smartHome.m_agent.agent.base_home_agent.run_ourAgent` 与 `smartHome.m_agent.memory.runtime_v1.DemoMemoryRuntime`，不是 experiments adapter。
- 结果根 `experiments/results/protocol_v4_2_supplemental_56e7528_20260816/` 保存了创建偏好、自然语言纠正、跨实体选择三条 pilot 的 JSON 与独立 SQLite。
- Python 3.11 / LangChain / LangGraph import 成功，模型实际进入 router、filter、`query_tool` 工具调用；但调用期间 API 出现 `400 upstream_unavailable`。
- 失败收尾又触发项目外 `try.memory` resolver 对不存在 SQLite 列 `code` 的查询，形成 `OperationalError: no such column: code`，从而掩盖初始 API 异常。
- 经用户授权，已在项目内创建 `experiments/external_dependency_backups/try_memory_pre_fts_escape_20260816.tar.gz` 的修改前备份（SHA-256：`68e97381553e2dfb92ef354d779299dd4e5c31753ae8c4d94c1fc1a08e33cbb5`），再对 `try/memory/sqlite_store.py` 作最小修复：将任意用户/LLM FTS 输入作为字面短语查询，避免 `Error code: 400` 中的冒号被 SQLite FTS 解析为不存在的 `code` 列。
- 该修复已在全新临时 SQLite 与 `try/memory` 的 8 项既有测试中通过；未读写 v4、v4.1 或旧 v4.2 的结果数据库和工件。修复后的 runtime 必须在新的 revision、全新结果根和全新 SQLite 上重新进行 1-replicate pilot，成功后才可考虑扩大，仍不得预先宣称产品 runtime 已验证。
- 重新 pilot 前，产品 runner 已改为每条轨迹独立子进程执行：父进程无论子进程成功、异常退出或超时，都会写入 canonical JSON、退出码、stdout/stderr 和 SQLite 路径。该变更只补齐审计落盘，不改变 `run_ourAgent`、`DemoMemoryRuntime`、场景文本或产品 Agent 的模型调用逻辑。
- 修复后 pilot 使用 revision `bfbf884` 与独立根 `experiments/results/protocol_v4_2_product_runtime_bfbf884_20260816/` 执行 `R1-R3 @ 1001`。三条均真实进入产品 Agent、LLM、`tool_filter`、设备查询和 `query_tool`，每个独立 SQLite 均保留 `19` 条 memory records 和 `1` 条 memory event；此前 `no such column: code` 未再出现。
- 三条轨迹均在后续模型调用收到 `400 upstream_unavailable` 后失败，worker 的原始 stderr、退出码和失败 JSON 均已留存。产品 runtime 当前未提供统一的 usage callback，故 runner 不能把日志中的响应 usage 安全地汇成 canonical usage，严格 usage gate 亦不通过。此根仅为失败的工程/runtime 稳定性证据，不能扩展至 10 replicates、不能进入论文补充表，也不能表述为完整产品 runtime 验证通过。
- 后续修复已在产品 `DemoMemoryRuntime` 增加 task-scoped telemetry：LangChain middleware 会将每个实际 `AIMessage` 的 usage metadata、model/provider 和 tool calls 写入当前 runtime task，runner 在成功或异常收尾时都写入 canonical JSON。该机制避免从文本日志推断 token，不修改 prompt、场景、Agent 决策或工具执行；下一次 runtime 重试将使用新 revision/new root 验证该审计字段。
- revision `84b06e6` 的 telemetry pilot 已在独立根 `experiments/results/protocol_v4_2_product_runtime_84b06e6_20260817/` 完成 `R1-R3 @ 1001`。三条均产生非零 canonical usage（合计 `52,693` prompt、`670` completion、`53,363` total tokens），记录 `15` 次真实 LLM response、`15` 个 tool call，且各 SQLite 保留 `19` 条 records/`1` 条 event；仍无 FTS `code` 错误。
- 但三条均在后续调用遭遇相同 `400 upstream_unavailable`，task_success 均为 false。因此该 root 的专项审计为 fail，不能扩展、不能作为性能结果。它确证了产品 runtime 已真实运行并且 usage/tool-call 审计现可用，但尚未证明端到端任务成功率。为避免在相同外部故障状态下无意义重复付费调用，本轮停止重试，等待上游恢复后必须使用新的 revision/new root 重启 gate。
- 为验证可恢复性，产品模型层现冻结一项受限 transport repair：仅当异常正文明确包含 `upstream_unavailable` 或“上游服务暂时不可用”时，在模型调用边界等待 0.75 秒后额外尝试一次；其他 400、解析错误、工具错误和模型行为均不重试。该 repair 不会重放工具或整条任务，SDK 隐式重试已设为 0。所有 attempt 会进入 task audit，再汇总到 canonical `transport_attempts`。两项离线边界测试与完整 smoke (`135/135`) 已通过；下一次实际 runtime pilot 将在新 revision/new root 中验证其效果。
- revision `a2cf215` 的 repair-enabled pilot 仍未通过：R1/R3 分别在后续模型请求收到 `APITimeoutError`，R2 收到代理 `500 get_channel_failed`，三条仍保存了真实 usage、工具调用和 SQLite。由于这些异常也是明确的代理 transport 条件，repair 分类已仅增加这两个签名（不接受任意 500）；全量 smoke 为 `136/136`。下一次 gate 仍至多在每个受影响的模型请求修复一次，并使用新 revision/new root。
- revision `342cfc6` 的扩大 repair pilot 已恢复 R1 与 R2：R1 记录三次“第一次失败、第二次成功”的 transport repair，R2 无需 repair 即完成。R3 仅在最后一个模型节点连续两次 `APITimeoutError` 后失败；其余调用、SQLite、usage 和工具调用均已保存。为避免将代理较慢的有效响应误判为失败，产品单请求 timeout 已从 30 秒提高至 90 秒；SDK 重试仍为 0，middleware repair 仍为一次上限。该调整经离线配置测试与完整 smoke (`137/137`) 验证，下一 gate 仍须使用新 revision/new root。
- 后续 `ed4f6ea` gate 仍由默认 `newapi/gpt-5.4-mini` 的间歇 `upstream_unavailable` 阻断（仅 R2 成功）；timeout 与一次 repair 均已实际触发并留痕，因此不再扩展同一代理的 retry 范围。项目配置内的独立 `my_gac/gpt-5.4` 通道已通过最小 `API_OK` probe（46 tokens）。产品 runtime runner 现支持仅对子进程生效的 `--provider` override，并把 provider/model 写入 canonical unit；它不改默认配置、不混合旧 root。完整 smoke 为 `138/138`；下一 runtime gate 将在独立 revision/root 上以该已验证通道重新执行，所有结果须按 provider 分开报告。
- `my_gac/gpt-5.4` 的独立 gate 使用 revision `f33d913` 与根 `protocol_v4_2_product_runtime_mygac_f33d913_20260817`：canonical rows 明确记录 `configured_provider=agent_provider=my_gac`，但 R1-R3 均在第一个模型请求收到 `503 proxy_unavailable: All accounts are currently unavailable`，没有模型响应、usage 或工具调用。该结果证明 provider override 生效，同时也确认当前两条独立外部 provider 通道都不可稳定运行完整产品 Agent；不得因先前极小 probe 成功而把它表述为 runtime 通过，也不应继续重复该调用。

## 真实 LLM 机制 Pilot

- 最完整 pilot 根：`experiments/results/protocol_v4_2_supplemental_e916a42_20260816/`；冻结 revision `e916a42654af929c1e616290ffaf4b9f1743e626`。
- 16/16 个 unit 均为 `external_llm`，均保存原始输出、transport attempt 与 token usage；无 heuristic fallback。
- 专项审计 `audits/mechanism_pilot_audit.json` 为 `fail`。未通过项包括 `-AsymFeedback`、`-Ripple` 的 target activation 缺失，以及 Ours 在 Governance、ConflictHandling、FeatureAbsorption、Ripple、Split 配对中的 operation/activation 缺失。
- 该结果说明当前严格结构化抽取已可让部分路径真实触发，但没有形成所有 8 个机制的有效配对矩阵。不得计算或报告 Ours-minus-ablation effect size、CI 或机制贡献大小。
- 后续逐 turn SQLite-context runner 在 revision `17cf081` 上再次执行 `16/16` pilot：它把每轮已持久化的 memory id 反馈给下一轮真实 LLM，仍有多个机制返回空操作。核验表明 M1、M6、M7、M8 等预注册自然语言没有在会话中建立目标机制所需的前置可引用记忆；在禁止 scenario patch、禁止 runner 补写 memory operation 的约束下，不能把空操作改写为 activation。因此该协议不能合规扩展到 10 replicates。

## 扩展 Longitudinal Pilot

- 结果根：`experiments/results/protocol_v4_2_longitudinal_e916a42_20260816/`；冻结 revision 同上。
- 矩阵为 Ours+B0-B5 × L2-L6 × 1 replicate，共 `35/35` trace，覆盖跨 session 更正、过期记忆、多实体污染、20/40/80 history growth、容量/长期冲突。
- B1 始终为 `raw_text_rag`，B4 始终为 `full_raw_history`；baseline fidelity 通过。
- strict audit 失败原因是 3 个 canonical external timeout：`Ours/L2`、`B1/L4`、`B5/L5`，其 usage 均为 0，未被删除或用 repair 覆盖。
- 其余 pilot 只作工程诊断：Ours `2/5`、B0 `0/5`、B1 `2/5`、B2 `3/5`、B3 `3/5`、B4 `4/5`、B5 `2/5`。这些不是论文统计结果。
- L5 中 B1 读取 81 条原始文档但仅保留 top-5，B4 读取完整 81 条；B4 `34,807` total tokens，高于 Ours `9,589`。这是 context-cost 行为证据，不是 10/30 replicate 推断。
- revision `b1fce52` 的第二个 longitudinal `35/35` pilot 已实施最多一次 transport repair，并输出 TSR/WDR/clustered CI；仍有 `B3/L3`、`B5/L2` 在两次 external timeout 后 canonical usage 为 0，strict audit 失败，故不得扩展到 10 replicates。该失败根保留在本地、按规则不纳入提交。

## 人工标注准备包

真人标注仍须按以下流程执行：

1. 两名标注者分别取得仅含场景原始输入和用户可观察结局的盲化任务包，不得查看系统名、模型输出、trace、MemoryRecord、evaluator 标签或对方答案。
2. 各自填写 `experiments/annotations/protocol_v4/inter_annotator/` 下对应 JSON 的 `annotator_a` 或 `annotator_b`。
3. 仅在两者标签不一致时，由第三人填写 `adjudication` 的身份、最终标签和裁决理由。
4. 执行 `PYTHONDONTWRITEBYTECODE=1 python3 experiments/scripts/compute_annotation_agreement.py --annotation-root experiments/annotations/protocol_v4/inter_annotator --output experiments/annotations/protocol_v4/annotation_agreement.json`。

在真实两人文件存在前，不得把 model-model κ=`0.5455` 称为人工 κ，也不得把 `human_annotation_complete` 改为 true。

## 后续恢复条件

1. 已获授权并完成 `try.memory` FTS 输入兼容修复、规范 usage/tool-call 捕获和受限 transport repair。默认 `newapi/gpt-5.4-mini` 仍间歇 400/timeout/channel failure，独立 `my_gac/gpt-5.4` 目前为 503 all-accounts-unavailable；待至少一个 provider 连续稳定后，以新的 revision/new root 重跑。三条轨迹均完整通过专项审计后才可扩大至 10 replicates。
2. 获得研究协议变更授权后，重新预注册一组在自然语言会话中先建立、后引用前序记忆的机制轨迹；不得覆盖现有 v4.2 pilot。所有 8 对在 1 replicate 同时通过 activation/isolation 后才运行 10 replicates。
3. 使用稳定外部 API 或获准调整 transport timeout 后，以新 revision/new root 重跑 longitudinal 1-replicate strict gate；全部 unit 有 canonical usage 后再扩展到 10 replicates。
